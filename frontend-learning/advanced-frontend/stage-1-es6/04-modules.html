📦 ES Modules 模块化

🤔 为什么需要模块化？

当项目变大，把所有代码写在一个文件里会变成"意大利面条" 🍝

模块化就是把代码按功能拆分成多个文件，每个文件只管一件事。

好处：

  • ✅ 代码更整洁、易维护
  • ✅ 可以复用
  • ✅ 避免命名冲突
  • ✅ 便于团队协作

📤 export — 导出

// ===== math.js =====
// 命名导出（可以导出多个）
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export function multiply(a, b) { return a * b; }

// 默认导出（一个文件只能有一个）
export default class Calculator {
  square(x) { return x * x; }
}

📥 import — 导入

// ===== app.js =====
// 导入命名导出
import { PI, add, multiply } from "./math.js";

// 导入默认导出
import Calculator from "./math.js";

// 全部导入为一个对象
import * as MathUtils from "./math.js";
console.log(MathUtils.PI);

// 重命名
import { add as sum } from "./math.js";

⚠️ 重要：浏览器中使用 ES Modules

<!-- 必须加 type="module" -->
<script type="module" src="app.js"></script>

<!--
  注意：
  1. 不能用 file:// 协议打开（双击）
  2. 必须通过服务器打开（VS Code Live Server 插件）
  3. 或者在命令行用 npx serve .
-->

📊 模块 vs 传统方式

对比传统 <script>ES Module
作用域全局，变量互相干扰每个文件独立作用域
加载方式同步，阻塞渲染异步，按需加载
依赖管理手动调整 script 顺序import 自动管理
复用性难导出/导入轻松复用

📌 总结

  • export — 导出变量/函数/类供其他文件使用
  • import — 从其他文件引入功能
  • export default — 默认导出（每文件一个）
  • type="module" — 在 HTML 中声明
  • Node.js 后端使用 CommonJS（require/module.exports），前端主要用 ES Modules
