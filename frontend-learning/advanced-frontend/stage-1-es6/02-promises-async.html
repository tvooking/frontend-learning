⏳ Promise 与 async/await

🤔 为什么需要异步？

JavaScript 是单线程的——一次只能做一件事。如果请求网络数据需要 3 秒，页面就会卡死 3 秒。

异步编程就是：不等待，先去做别的事，等数据回来了再处理。

📜 回调地狱 Callback Hell（旧方式）

// ❌ 嵌套太多，难以维护
getUser(1, (user) => {
  getPosts(user.id, (posts) => {
    getComments(posts[0].id, (comments) => {
      console.log(comments);
    });
  });
});

这就是为什么需要 Promise！

🤝 Promise 是什么？

Promise 就像一个外卖订单：

  • pending（等待中） — 订单已下，还没送到
  • fulfilled（已完成） — 外卖送到了 ✅
  • rejected（已拒绝） — 外卖送不了 ❌
// 创建一个 Promise
const order = new Promise((resolve, reject) => {
  // 模拟 2 秒后送达
  setTimeout(() => {
    const success = true;
    if (success) {
      resolve("🍔 外卖到了！");
    } else {
      reject("😢 送不了...");
    }
  }, 2000);
});

// 使用 Promise
order
  .then(result => console.log(result))  // 成功时
  .catch(error => console.log(error));  // 失败时

⚡ async/await — 更优雅的方式

// async 声明异步函数
async function getOrder() {
  try {
    const result = await order;  // await 等待 Promise 完成
    console.log(result);          // "🍔 外卖到了！"
  } catch (error) {
    console.log(error);           // 处理错误
  }
}

// 💡 await 只能在 async 函数内部使用
// 💡 try/catch 用于处理错误，相当于 .catch()

async/await 让异步代码看起来像同步代码，更容易阅读和维护。

📊 实际应用：并行请求

使用 Promise.all() 同时请求多个数据：

async function getDashboardData() {
  const [user, posts, notifications] = await Promise.all([
    fetchUser(),           // 获取用户信息
    fetchPosts(),          // 获取文章列表
    fetchNotifications()   // 获取通知
  ]);
  return { user, posts, notifications };
}

📌 总结

  • Promise — 解决回调地狱
  • .then().catch() — Promise 的链式调用
  • async/await — 让异步代码更可读
  • try/catch — 处理 await 中的错误
  • Promise.all() — 并行执行多个 Promise
